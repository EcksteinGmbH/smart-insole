# 智能鞋垫固件烧录测试结果

**通过。** 固件已经实际写入智能鞋垫 ESP32-C3，bootloader、分区表和应用程序均通过写后哈希校验。设备能够正常启动、初始化 IMU、开始 BLE 广播，并通过不触发电机振动的 BLE 接口自检。

```bash
idf.py -p /dev/ttyACM0 flash
```

| Flash 地址 | 内容 | 写入结果 |
|---:|---|---|
| `0x00000000` | bootloader，20864 字节 | 成功，哈希校验通过 |

写入完成后设备通过 RTS 自动硬复位，烧录工具正常退出，没有报告写入失败或校验错误。

## 5. 启动检查

启动日志确认：

- ESP-IDF v5.4.1 bootloader 正常运行；
- 识别到 4 MB Flash，DIO 模式，80 MHz；
- 从 `0x10000` 的 factory 分区加载应用；
- 应用版本和编译时间与本次构建一致；
- 电机、按键、LED、电池监测、BLE 和 IMU 初始化流程开始；
- BLE 正常开始广播；
- 未发现崩溃、异常重启或 panic。

本发布包内的启动日志副本：[`启动日志.log`](启动日志.log)（仅去除了串口文本的行尾控制字符；原始日志仍保存在项目 `logs/` 目录）。

## 6. BLE 非振动自检

执行命令：

```bash
tools/ble_test.sh --address 30:ED:A0:80:9A:6E selftest
```

结果：**25/25 通过**。

通过项目包括：

- `info_get`：电量、电压和充电状态字段正常；
- 两颗 IMU 的 `imu_get` 正常；
- API 文档字段 `acc_sleep_thresh`、`acc_sleep_after_s` 读写正常；
- IMU 参数修改后可以正确读回，测试结束后已恢复为 125 mg / 120 s；
- 三个电机的 `motor_get` 状态查询正常；
- IMU、电机的非法 ID 和缺少参数错误分支返回正确；
- 未知命令保持当前实现的不响应行为；
- 所有检查均未触发电机实际振动。

自检时设备报告电池电压约 4.069 V、电量 100%，状态为正在充电。

## 7. 已知提示与本次未测项目

- 启动日志提示硬件没有 32.768 kHz 晶振，因此 BLE 开启时自动 light sleep 不能生效。这是项目已有硬件特性，不是本次固件引入的新故障。
- 本次没有执行三个电机的实际振动测试。
- 本次没有重新执行 IMU 连续数据流速率和坏帧测试；此前项目基线为约 33.5 帧/秒、0 坏帧。

## 8. 最终判定

本次固件构建、烧录、启动和基础 BLE 接口检查均通过，可以作为当前智能鞋垫测试固件使用。电机实际振动和长时间 IMU 数据流属于后续可选的硬件功能验证，不包含在本次通过范围内。
