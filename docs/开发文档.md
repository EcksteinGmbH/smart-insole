## 1. 项目概况

鞋垫内置 ESP32-C3，通过两颗 IMU 采集脚部运动，经 BLE 推送给手机 App；App 下发命令驱动 3 个脚趾振动电机反馈。

| 资料 | 位置 | 地位 |
|---|---|---|
| 硬件配置和软件功能说明 V0.3 | `硬件配置和软件功能说明V0.3.xlsx`（sheet「硬件配置」「修改记录」） | 硬件引脚与功能需求的权威来源 |
| 智能鞋垫 API 文档 V1.0.0 | `《智能鞋垫API文档V1.0.0》.docx` | **BLE JSON 接口契约，已交付 App 开发工程师；固件必须以它为准** |
| 固件工程 | `firmware/`（ESP-IDF，工程名 `xrs_code`） | 当前唯一代码基线（非 git 仓库） |
| 出厂固件备份 | `firmware_backup/flash_full_20261009_1454.bin`（+ `.sha256`） | 接手时设备上的整片 4MB flash |

**重要现状**：固件中**没有**计步/步态识别算法。当前模式是固件推原始 IMU 数据 → 手机判断 → 手机下发 `motor_set`。

## 2. 硬件

| 功能 | GPIO | 说明 |
|---|---|---|
| I2C SCL / SDA | 0 / 1 | 两颗 LSM6DS3TR-C：IMU1=`0x6A`（代码 `imu[0]`），IMU2=`0x6B`（代码 `imu[1]`）；代码 I2C 1 MHz |
| 电池电压 ADC | 2 | 规格：0.75×Vbat 分压；**代码按 0.5 分压计算**（待确认，见 §8） |
| USB 5V 检测 / 唤醒 | 3 | 高 = USB 插入；深睡唯一唤醒源 |
| IMU INT2 | 4 | 规格表 V0.3 前后矛盾（IMU1 还是 IMU2 接 GPIO4）；当前固件**未使用** IMU 唤醒 |
| 电机 DRV1/2/3 | 5 / 6 / 7 | 大/中/小脚趾，LEDC 5 kHz PWM，13 bit |
| 红 LED / 充电指示 | 8 | 规格表同时写成充电芯片 CHARGER 脚；代码当 LED 输出 |
| 按键（Strapping/休眠） | 9 | 长按 5 s → 进深睡（仅 USB/复位唤醒） |
| 绿 LED / 充满指示 | 10 | 规格表同时写成 STDBY 脚；代码当 LED 输出 |
| USB D- / D+ | 18 / 19 | 内置 USB-Serial/JTAG |

实测芯片：ESP32-C3 AZ (QFN32) rev v1.1，内置 4MB flash (XMC)，40 MHz 晶振，无 32 kHz 晶振；芯片 MAC `30:ed:a0:80:9a:6c`，BLE 地址 `30:ED:A0:80:9A:6E`，广播名 `ESP32C3_XRS`。

## 3. 软件架构

ESP-IDF v5.4.1 + FreeRTOS + NimBLE。PM 动态调频 40–160 MHz + tickless idle 自动 light sleep。

| 模块 | 文件 | 要点 |
|---|---|---|
| 入口 | `main/main.c` | 初始化顺序：电机 → NVS → PM → 电池 → 按键 → LED → BLE → IMU → 休眠任务；`ble_imu_notify_task` 每 30 ms 发 IMU 帧 |
| BLE | `main/src/nimble.c` | Service 0xFFF0；0xFFF2 write（命令）、0xFFF1 notify（JSON 响应）、0xFFF4 notify（IMU 流）；断开后自动重新广播 |
| 协议 | `main/src/protocol.c` | JSON 帧按花括号重组（384 B 缓冲，1 s 超时）；命令见 §4 |
| IMU | `main/src/app_lsm6d.c` | 52 Hz，±4 g，500 dps，轮询；用芯片 activity/inactivity 得 `is_inactive`；休眠阈值寄存器 1 LSB = 62.5 mg |
| 电机 | `components/motorx/` + `components/motor/` | 每次启动建一个任务，按 freq/duty 开关 times 次；intensity 200–1000 映射 PWM 占空比 |
| 电池 | `components/bat/` + `main/src/app_bat.c` | ADC 按需连续采样 64 点 + EWMA；百分比在 `BAT_P0_VOLTAGE`=3.6 V ~ `BAT_P100_VOLTAGE`=4.05 V 线性 |
| 休眠 | `main/src/app_wakeup.c` | 三条路径：IMU 长期静止 / 低电量 / 长按；进入前红灯闪 3 次；仅 GPIO3（USB）唤醒；USB 在线时不休眠 |
| LED/按键 | `main/src/app_led.c` / `app_button.c` | 开机绿灯闪 3 次；充电红灯 0.5 s 闪，充满绿灯常亮 |

任务优先级见 `main/bsp.h`（电机 10 > LED 9 > NimBLE 8 > 其他 5）。

### IMU 二进制帧（0xFFF4，API 文档未覆盖，App 需要）
```
55 AA LEN | IMU0: ax ay az(mg) gx gy gz(mdps) | IMU1: 同 | SUM
LEN = 1 + 24 × 使能的 IMU 数（两颗都开 = 49，整帧 52 字节）
float32 小端；SUM = (LEN 字节 .. 最后一个数据字节) 求和 & 0xFF
```
需要 MTU ≥ 55（实测 BlueZ 自动协商到 256）。

## 4. BLE JSON 接口（以 API 文档 V1.0.0 为准）

所有值均为**字符串**。批量：`motor_set id="3"`、`imu_set id="2"`。

| cmd | 请求字段 | 响应字段 | 错误码 |
|---|---|---|---|
| `motor_set` | id, freq, duty, times, [intensity=800] | cmd,id,freq,duty,times,intensity,run,count,err,msg | -1 id>3 / -2 no id / -3 params missing |
| `motor_get` | id(0–2) | 同上 | -1 id>=3 / -2 |
| `imu_set` | id(0–2), [enable], [acc_sleep_thresh], [acc_sleep_after_s] | cmd,id,[enable],[acc_sleep_thresh],[acc_sleep_after_s],err,msg | -1 id>2 / -2 |
| `imu_get` | id(0–1) | cmd,id,enable,freq,acc_sleep_thresh,acc_sleep_after_s,err,msg | -1 id>=2 / -2 |
| `info_get` | — | cmd,bat("xx.x%"),voltage,charging(yes/no),err,msg | — |

未知命令：固件不回包。

原则：所有 AI/开发工具只装在本项目范围（`.mcp.json`、`.claude/`、`.vscode/`、`tools/.venv`），不改全局配置。

### 调研结论（2026-10）：不引入 ESP32 专用第三方 MCP
- Claude Code + bash + idf.py 已覆盖编译/烧录/JTAG；社区 idf.py 封装、串口 MCP、GDB MCP 无增益且有供应链风险。
- 官方 `idf.py mcp-server` 需 IDF ≥ 6.0，不适用。
- 真正的缺口已补：非交互日志（`tools/capture.sh`）、芯片资料（官方文档 MCP）、BLE 闭环测试（`tools/ble_test.sh`）。
- 可选未做：Context7（有 IDF v5.4.1 库，但与本地源码重复）；LSM6DS3TR-C 数据手册 / ST 驱动 `STMicroelectronics/lsm6ds3tr-c-pid` 可下载到 `docs/` 备查。

## 6. 日常工作流

在 `firmware/` 下（先 source export.sh）：

```bash
idf.py build                                  # 编译（产物 build/xrs_code.bin，app 分区 1MB，当前占用 ~65%）
idf.py -p /dev/ttyACM0 flash                  # 烧录 —— 必须先征得用户同意
```

在项目根目录：

```bash
tools/capture.sh 20                           # 复位后抓 20 s 日志 → logs/monitor_*.log（ELF 回溯解码）
tools/capture.sh 30 "Advertising started"     # 等到正则匹配，30 s 超时退出码 110
tools/capture.sh 60 "" --no-reset             # 不复位旁听

tools/ble_test.sh --timeout 6 scan            # 全局参数放在子命令前
tools/ble_test.sh --address 30:ED:A0:80:9A:6E selftest            # API 文档一致性自检（不振动）
tools/ble_test.sh --address 30:ED:A0:80:9A:6E selftest --motors   # 含三电机实际振动
tools/ble_test.sh --address 30:ED:A0:80:9A:6E selftest --robustness  # 发数字类型字段
tools/ble_test.sh --address 30:ED:A0:80:9A:6E stream --seconds 10 [-v]
tools/ble_test.sh --address 30:ED:A0:80:9A:6E cmd '{"cmd":"info_get"}'

tools/generator_test.sh ports             # 列出 WT9011DCL-RF 主机串口
tools/generator_test.sh web               # 启动本地网页工作站并打开浏览器
tools/generator_test.sh simulate --help   # 无硬件验证发电机测试链路
tools/generator_test.sh capture --help    # 采集实物试次
tools/generator_test.sh compare --help    # 聚合对比 T0/T1
```

线性发电机测试的完整流程、指标定义和数据目录见 [线性发电机测试工作站.md](线性发电机测试工作站.md)。

- **禁止**交互式 `idf.py monitor` / `menuconfig`（需 TTY）。改 Kconfig：直接编辑 `sdkconfig`（LF 换行）→ `idf.py reconfigure && idf.py build`，并 diff 确认。
- 深度睡眠时 `/dev/ttyACM0` 会消失，capture 会等待重连（不复位）。
- JTAG：后台 `idf.py openocd`，`riscv32-esp-elf-gdb -batch -ex "target extended-remote :3333" -ex "mon reset halt" -ex bt build/xrs_code.elf`。
- 恢复出厂固件：
  ```bash
  sha256sum -c firmware_backup/flash_full_20261009_1454.bin.sha256
  esptool.py --chip esp32c3 -p /dev/ttyACM0 write_flash 0 firmware_backup/flash_full_20261009_1454.bin
  ```

## 9. 测试基线

### 9.1 当前固件（2026-10-09 15:08 编译并烧录，含 §8 改动）
- `selftest --robustness --motors`：**34/34 通过**（`logs/ble_selftest_newfw.txt`）；三电机实测振动正常，motor 0 两次后 run=0,count=2。
- USB 口可见完整应用日志（`tools/capture.sh`）。
- `stream`：33.5 帧/秒，52 字节/帧，0 坏帧（`logs/ble_stream_newfw.txt`）。
- **新发现 1（功耗）**：启动日志 `BLE_INIT: 32.768kHz XTAL not detected ... light sleep mode will not be able to apply when bluetooth is enabled` —— 硬件无 32 kHz 晶振，**BLE 开启时自动 light sleep 永远不生效**，sdkconfig 中的 PM/tickless 省电配置实际无效。
- **新发现 2（数据有效性）**：静止时 IMU 进入芯片 inactivity 模式（`act_mode = XL_12Hz5_GY_PD`）：加速度降到 12.5 Hz，**陀螺仪掉电，BLE 帧中的陀螺值冻结为最后一次读数（非零，如 2082 mdps）**；`imu_get` 的 freq 读回 ~13 Hz。BLE 仍按 33 Hz 发帧（重复数据）。App 侧可能把冻结的陀螺值误判为转动。

### 9.2 出厂固件（接手时，2026-10-09）

- 出厂固件：编译于 2025-10-28，镜像头 flash size=2MB（与仓库 sdkconfig 的 4MB 不同 → 源码与设备固件可能不完全一致）。
- `selftest`：**19/25 通过**（`logs/ble_selftest_oldfw.txt`）。失败均为 imu 字段名问题：按文档字段 `imu_set` 被静默忽略却返回 `err:"0"`；响应缺 `acc_sleep_after_s`。
- 默认休眠阈值读回 **125 mg**（文档写 150，寄存器量化所致）。
- `stream`：33.3 帧/秒，52 字节/帧，0 坏帧（`logs/ble_stream_oldfw.txt`）；静置时两颗 IMU |a|≈1 g，陀螺零偏 2–4 dps。
- 编译警告 13 个（未使用变量、`ADC_ATTEN_DB_11` 弃用、`app_wakeup.c:126` fall-through）。
